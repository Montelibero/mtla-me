# Montelibero Association Landing

Minimal multilingual landing page for the Montelibero Association.

## Project structure

```text
.
├── index.html             # Root redirect / noscript ({{{BUILD_*}}} filled by scripts/build.mjs)
├── template.html          # Shared HTML template for locale pages
├── assets/                # CSS and minimal client-side JS
├── i18n/
│   ├── links.json         # Shared external links used by locale content
│   └── */content.json     # Per-locale content source
├── documents/             # Source Markdown documents
│   └── UPSTREAM.json      # Authoritative repository commit and document hashes
├── scripts/
│   ├── build.mjs          # Static-build orchestration to _site/
│   ├── agreement.mjs      # Markdown rendering and sanitization
│   ├── html.mjs           # Escaping, templates, and safe links
│   ├── metadata.mjs       # JSON-LD, locale alternates, and sitemap
│   ├── schema.mjs         # Content validation before render
│   └── verify-documents.mjs # Agreement provenance verification
├── test/                  # Redirect and generated-site regression tests
├── _site/                 # Generated artifact (ignored; never edit or commit)
├── Dockerfile             # Container image for local preview
└── .github/workflows/     # GitHub Pages deployment
```

## How it works

- `scripts/build.mjs` renders all locale pages from one template, writes the root redirect page, and generates the sitemap and machine-readable metadata
- `assets/redirect.js` chooses a locale from `?lang=`, then `navigator.languages`, without storage or tracking; the build inlines it behind an exact CSP hash so redirecting has no extra request, while `<noscript>` contains direct language links
- `documents/Agreement.en.md` and `documents/Agreement.ru.md` are sanitized and rendered only at build time. Locale pages contain no runtime JavaScript
- `documents/UPSTREAM.json` pins the authoritative documents repository commit and SHA-256 digest for both agreement copies; every build verifies them
- Shared repeated URLs live in `i18n/links.json`
- `scripts/schema.mjs` validates exact content shapes, HTTPS links, agreement-language mapping, and cross-locale structural parity
- GitHub Pages deploys only the generated `_site/` artifact from the `v2` branch workflow

## Supported languages

- English (`en`)
- Russian (`ru`)
- Spanish (`es`)
- Montenegrin (`cnr`, retained at the established `/sr/` URL and selected for
  Montenegrin, Serbian, Bosnian, and Croatian language preferences)

## Development

Node.js 24 LTS or newer is required.

```bash
npm ci
npm run check
./serve.sh
```

Then open `http://127.0.0.1:8080`.

Use `npm run build` when only a fresh `_site/` artifact is needed. `npm run check` is the required pre-commit command: it verifies document provenance, rebuilds from a clean output directory, and runs the generated-site and redirect tests.

## Editing content

- Edit shared structure only in `template.html`, shared URLs in `i18n/links.json`, and localized copy in the relevant `i18n/<locale>/content.json` file.
- Keep the stable item order and keys identical across locales. The build fails if a locale drifts structurally.
- Do not hand-edit `_site/`; its `sitemap.xml` is generated by the build.
- Follow the agreement update procedure in [INSTALL.md](INSTALL.md) whenever an upstream agreement changes.

## Deployment

- Merge an approved pull request into `v2` to trigger the GitHub Pages workflow
- Production uses the custom domain `mtla.me`
- Pull requests and pushes run the same locked build and tests; only the `v2` branch can upload and deploy `_site/`
- The build publishes named public assets and generated pages and agent resources. Internal Markdown, local production notes, and audit reports are excluded from `_site/`.

Docker preview uses the same build output:

```bash
docker build -t mtla-landing .
docker run --rm -p 127.0.0.1:8080:80 mtla-landing
```
